## 1. Data build is reproducible

```
python3 scripts/build-data.py
```

Writes 12 Lotto and 11 EuroMillionen files to `dcupl/data/` and logs exactly the 6 documented
deviations from the sources - no more, no less:

```
WARN lotto-ziehungen-1986-2000_ATS.csv: identical duplicate line for 03.01.1999 skipped
WARN lotto 04.07.2004: drawn order [45, 19, 35, 20, 2, 35] does not match ascending numbers [2, 19, 20, 32, 35, 45] -> drawn order dropped
WARN lotto 09.05.2010: ascending/drawn columns swapped in source -> swapped back
WARN lotto 05.02.2017: drawn order [6, 44, 30, 32, 41, 44] does not match ascending numbers [6, 7, 30, 32, 41, 44] -> drawn order dropped
WARN euml 07.09.2007: drawn order [43, 3, 34, 2, 33]/[5, 3] does not match ascending numbers [2, 3, 33, 34, 42]/[3, 5] -> drawn order dropped
WARN euml: source date 20.11.2099 -> 20.11.2009
6 warnings
```

The build is idempotent: re-running it leaves every file in `dcupl/data/` byte-identical
(verified by comparing MD5 sums of all 23 files before and after; `git status dcupl/data` shows
no change attributable to the run).

## 2. Loader, models and data load cleanly

```
npm run validate          # = npx dcupl validate --json
```

```json
{
  "ok": true,
  "load": { "ok": true },
  "models": { "total": 2, "empty": [], "autoGenerated": [] },
  "errors": { "bySeverity": { "critical": 0, "warning": 22271 },
              "byGroup": { "PropertyDataError": 22271 },
              "byType":  { "UndefinedValue": 22271 } },
  "summary": { "critical": 0, "warnings": 22271 }
}
```

`critical: 0` is the pass criterion. The 22,271 warnings are all `UndefinedValue` on legitimately empty
cells - prize tiers that did not exist yet (4+ZZ, 3+ZZ, ZZ before September 2010; EuroMillionen 2+0 before
May 2011), Austrian winner counts before 2011, the drawn order after 2016, and `fiveAddNrJackpot`, which is
only set when that tier rolled over. They are a property of the data, not a defect.

### Prize rates parse with a decimal point

```
npx dcupl app fn aggregate --app <appId> --model lotto --attribute rateThree --types min,max,avg --json
```

```json
{"attribute":"rateThree","types":["min","max","avg"],"min":2.69,"max":70,"avg":12.789120521172633}
```

`min: 2.69` is the regression check for the decimal-comma bug: while `5,20` was parsed as `5`, the minimum
of this column was an integer `2`.

### Draws per year

```
npx dcupl app fn facets --app <appId> --model lotto --attribute year --sort value-desc --limit 3 --json
```

```json
[{"value":2026,"count":94},{"value":2025,"count":124},{"value":2024,"count":114}]
```

Counted from the data (`awk -F';' 'NR>1{c[$1]++}'` per year file): 2024 = 52 Sundays + 52 Wednesdays +
10 Fridays = 114, 2025 = 52 + 53 + 19 = 124, 2026 = 38 + 37 + 19 = 94 up to the latest draw on 20.09.2026.
The Friday draws are monthly (2nd Friday, no June and no December) in 2023 and 2024, monthly until
11.07.2025 and every two weeks from 25.07.2025 on - not weekly.

### EuroMillionen draw days

```
npx dcupl app fn facets --app <appId> --model euromillionen --attribute weekday --json
```

```json
[{"value":"Friday","count":1177},{"value":"Thursday","count":1},{"value":"Sunday","count":2},
 {"value":"Tuesday","count":800},{"value":"Wednesday","count":1}]
```

1177 + 800 + 4 = 1981, matching `currentSize`. Friday only until May 2011, Tuesday and Friday since;
the four remaining draws are holiday moves.

### Dates parse as UTC

Both models declare `"UTC": true` on the `date` property (`PropertyDate.UTC`, confirmed via
`npx dcupl schemas get Property`).

```
npx dcupl app query execute --app <appId> --model lotto \
  --query '{"operator":"eq","attribute":"year","value":2026}' \
  --limit 3 --projection '["date","year","weekday"]' --json
```

```json
[{"date":"2026-01-04T00:00:00.000Z","year":2026,"weekday":"Sunday"},
 {"date":"2026-01-07T00:00:00.000Z","year":2026,"weekday":"Wednesday"},
 {"date":"2026-01-09T00:00:00.000Z","year":2026,"weekday":"Friday"}]
```

Without `UTC: true` the same draw came back as `2026-01-03T23:00:00.000Z` - local midnight in
Europe/Vienna, which puts the draw on the previous calendar day in UTC. Setting the flag changed
nothing else: record counts, aggregates and facets above were identical before and after.
